## 3. The 9-step migration protocol (per store)

Apply independently to each store that is migrated. No step may be skipped. No step is irreversible until Step 9 approval.

### Step 1 — Identify consumers

- Enumerate every importer/caller of the store's owner module (grep `from memory.conversation_store`, `WorkspaceManager(`, `skyfall_memory`).
- List processes that open the file (GUI, MCP child, worker threads, harnesses, tests).
- Record in the migration ticket. For `workspace_index.db`, include the MCP child and any active scan workers.

### Step 2 — Capture current schema

- Read-only: open with `file:...?mode=ro` URI or `sqlite3` connection in read-only mode.
- Dump DDL: `SELECT sql FROM sqlite_master WHERE type IN ('table','index','trigger','view');`
- Record `PRAGMA user_version`, `PRAGMA page_size`, `PRAGMA journal_mode`, `PRAGMA foreign_keys`.
- Save to `audits/migrations/<store>_<date>_schema_before.sql` (documentation only; no DB write).

### Step 3 — Verified backup

- Use sqlite3 Online Backup API (safe while DB may be in WAL mode):
  - Python: `src.backup(dst)` on a read-only connection, or
  - CLI if available: `sqlite3 <db> ".backup <dest>"` (not available in this environment per Phase 0; use Python).
- Backup destination: a timestamped copy outside the live data dir and outside OneDrive-synced repo paths where possible, e.g. `%LOCALAPPDATA%\SKYFALL\backups\<store>_<ISO8601>.db`.
- Also copy WAL/SHM sidecars if present (`-wal`, `-shm`) alongside, OR checkpoint first (`PRAGMA wal_checkpoint(TRUNCATE)`) on a read-only-safe connection only if no writers are active.
- Record SHA-256 of backup and live DB.

### Step 4 — Test on a separate copy

- Never test on the live DB. Restore/copy the backup to a scratch path (e.g. `%TEMP%\skyfall_migration_test\<store>.db`).
- Apply the candidate migration (schema change + data transform) to the scratch copy only.
- Keep the live DB untouched during this step.

### Step 5 — Verify integrity

On the migrated scratch copy:
- `PRAGMA integrity_check;` → must return `ok`.
- `PRAGMA foreign_key_check;` → must return no rows.
- `PRAGMA quick_check;` as a faster cross-check.

### Step 6 — Compare counts and identifiers

- For every table: row count before vs after (must match unless migration intentionally dedupes, which requires explicit approval).
- Identifier preservation: every primary key / foreign key value before must exist after (set equality). For `conversations.id`, `messages.id`, `workspaces.id`, `workspace_files.id`, and any `copilot_session_id`.
- Conversation/message counts per conversation unchanged.

### Step 7 — Verify relationships and constraints

- Re-run `PRAGMA foreign_key_check`.
- Validate application-level invariants: e.g. every `messages.conversation_id` resolves; every `workspace_files.workspace_id` resolves; active conversation pointer in `app_state` still valid; no orphan rows.
- If FTS/index added, verify query results match LIKE baseline on sample.

### Step 8 — Document rollback

- Write rollback procedure before any irreversible step: restore backup copy over live file (with all processes stopped), re-verify integrity + counts, restart consumers.
- Include: stop conditions (which process signals), file paths, SHA-256 verification, sidecar handling, and a "if restore fails" escalation.
- Record in `audits/migrations/<store>_<date>_rollback.md`.

### Step 9 — Explicit approval before irreversible change

- No live-DB modification without written approval in the progress record / decision log.
- Approval must name: store, migration, approver, date, backup path + hash, and the tested scratch copy path.
- Irreversible = any write to the live file, including schema version bump. Read-only inspection and scratch-copy testing do not require this gate.

## 4. Backup commands (read-only safe)

Python (preferred; sqlite3 CLI not available in this environment):

```python
import sqlite3, hashlib, shutil, datetime, os

def backup_db(src, dst_dir):
    os.makedirs(dst_dir, exist_ok=True)
    stamp = datetime.datetime.now().strftime("%Y%m%dT%H%M%S")
    dst = os.path.join(dst_dir, f"{os.path.basename(src)}.{stamp}.bak")
    # read-only source connection
    src_conn = sqlite3.connect(f"file:{src}?mode=ro", uri=True)
    dst_conn = sqlite3.connect(dst)
    src_conn.backup(dst_conn)   # Online Backup API
    dst_conn.close(); src_conn.close()
    # hash both
    def sha(p):
        h = hashlib.sha256()
        with open(p, "rb") as f:
            for chunk in iter(lambda: f.read(65536), b""):
                h.update(chunk)
        return h.hexdigest()
    return dst, sha(src), sha(dst)
```

Notes:
- `mode=ro` guarantees no write to source.
- `connection.backup()` is safe with WAL; it handles `-wal`/`-shm` internally.
- If a checkpoint is desired, do it only when no writers are active and only on the scratch copy, never on live during investigation.

## 5. Copy-test procedure (summary)

1. Quiesce consumers (GUI closed, MCP child stopped, no scan workers, tests not running).
2. Backup live DB (Step 3) → record hash.
3. Copy backup to scratch dir.
4. Apply migration to scratch copy.
5. Run Steps 5–7 on scratch copy.
6. If all pass, request Step 9 approval.
7. After approval: repeat backup (fresh), apply migration to live, re-verify Steps 5–7 on live, restart consumers, smoke-test.

## 7. Rollback steps (per store)

1. Stop all consumers (GUI, MCP child, workers, tests).
2. Verify backup hash matches recorded hash.
3. Replace live DB file with backup copy (and remove stale `-wal`/`-shm` sidecars first, or checkpoint).
4. Run `PRAGMA integrity_check` and `PRAGMA foreign_key_check` on restored file.
5. Re-run count/ID comparison against pre-migration recorded values.
6. Restart consumers; smoke-test (open app, list conversations, run a workspace scan).
7. If restore fails or hashes mismatch: escalate; do not delete backup; preserve live file under a `.failed` suffix.

Sidecar retention note: WAL/SHM sidecars (`*.db-wal`, `*.db-shm`) must be removed or checkpointed before file replacement to avoid stale-WAL corruption. Record their presence in Step 2.
