# V1.0.1-AUTH-CONSOLIDATION

## Phase 7 — Authentication Source Consolidation

### Overview

This document consolidates the authentication source state for Skyfall v1.0.1. Per Decision 7 (PENDING in Architecture Decisions), the auth source choice between MSAL and Azure CLI remains under evaluation. For Phase 7, the auth source decision is held for Phase 8 migration, and both code paths are maintained without prejudice.

### Current Auth Source State

#### Azure CLI Path (Active)

- **Identity service**: `skyfall_cloud.identity_service`
- **Auth mechanism**: Azure CLI profile authentication (`az profile get-access-token`)
- **Power Platform integration**: AzureProfileManager for profile state aggregation
- **Status**: Implemented and wired; Azure CLI primary, MSAL read-only for migration
- **Dependencies**: Azure CLI installed and configured; no MSAL client ID required
- **Risk level**: Low for existing users with Azure CLI profiles

#### MSAL Path (Retained, Not Primary)

- **Identity service**: `skyfall_cloud.identity_service` (dual code path)
- **Auth mechanism**: MSAL (Microsoft Authentication Library) with client ID/configuration
- **Status**: Code path retained but not primary; MSAL read-only for migration
- **Dependencies**: MSAL packages, client ID environment variables, token caches (DPAPI)
- **Risk level**: Higher configuration complexity; requires client ID setup

### Decision Status

- **Decision 7** (Architecture Decisions): PENDING — Auth source: MSAL vs Azure CLI
- **Phase 7**: Both code paths maintained; no removal of either
- **Phase 8**: Auth source decision will finalize single canonical path
- **No decision presumed** in any Phase 7 documentation (Decision 10 references removed from defect disposition)

### Migration Implications

- Profile registries differ: Azure CLI uses isolated config dirs; MSAL uses DPAPI caches
- Existing profiles must be preserved under either choice
- No secrets stored in either auth path; secret-free health view maintained
- Both paths support the same functional capabilities (health view, account state aggregation)

### Security Implications

- Azure CLI: isolated config dirs, no credential storage in code
- MSAL: DPAPI caches, client ID configuration required
- Both paths: secret-free health view; no credential leakage through logs
- Redaction (H-02) applied before any export/export operations

### Decision Numbering Reconciliation

- Previous documentation referenced "Decision 10: Azure CLI primary, MSAL read-only for migration"
- This has been reconciled: Decision 7 is the auth source decision in Architecture Decisions
- All Phase 7 documentation now avoids prescribing a decision number, consistent with holding the decision for Phase 8

### Recommendation

- Maintain both auth source code paths through Phase 7
- Finalize Decision 7 in Phase 8 to select canonical auth source
- No code deletion or path removal during Phase 7
- Document baseline auth state for migration decision in Phase 8
