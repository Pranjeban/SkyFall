## B. Ranked architecture risks (v1.0.1 / v1.1)

1. **Toolchain not demonstrably executable (highest).** No runner config, broken venv (reported), unused declarations, deprecated SDK pin. No later change can be validated.
2. **Zero automated coverage of runtime paths.** The 3,358-line `main_window.py`, MCP child spawn, `CopilotWorker`, two Qt workers, and `skyfall_mcp/server.py` have no test imports.
3. **Lifecycle and process boundary concentrated in one monolith.** `MainWindow.__init__` owns 2 SQLite stores, 2 JSON registries, 11 pages, and a QThread spawning a child Python process inheriting `PATH`, `LOCALAPPDATA`, `AZURE_CONFIG_DIR`. Shutdown is best-effort (5 s waits).
4. **Memory ownership split and mis-documented.** Two SQLite DBs + 2 JSON registries + MSAL caches + separate SDK transcripts + orphan DB; a prior audit falsely claimed runtime writes to the orphan.
5. **"Dormant" layers are implemented and tested.** Six real services plus two zero-importer implemented services plus `backend/api.py` plus empty `execution/*` → risk of reimplementation or wrong wiring assumptions.
6. **No application-level observability.** Only WARNING-to-stderr in the MCP child; empty `logs/`; no excepthook/faulthandler.
7. **Execution and audit not foundation-ready.** `operations_service.py:16-19` returns a placeholder "delegated to controlled runner" with no runner; `execution/*` empty; `AuditService` in-memory only (`audit_service.py:13-28`); SDK permission approval is one-time and allow-list based (`copilot_service.py:304-317`).
8. **Release identity drift.** `0.9.2` in `main.py:17`, `capabilities.json:6`, `server.py:47`, `copilot_service.py:313` vs `1.0.1` in `backend/api.py:14` and audit filenames.

## C. Recommended Phase 6 foundations scope

**MUST correct first (enabling work only):**
- Establish a reproducible interpreter/dependency baseline; resolve cp315/PyYAML and PySide6 constraints; decide (not silently migrate) the Copilot SDK pin; justify or remove unused declarations. Confirm external-research assumptions before acting.
- Make the existing 90 tests executable: minimal runner configuration and a working environment. Add small **characterization** tests using the existing `SKYFALL_TEST_MODE` hard blocks (`command_runner.py:75`, `accounts.py:70,171`, `azure_resources.py:349`) for startup/shutdown and MCP child spawn — not a full GUI suite.
- Freeze the memory ownership map as documentation/guard tests. **Do not migrate anything based on the retracted audit claim.**
- Add minimal diagnostics: local file logging plus an unhandled-exception hook; keep MCP stdout clean (`server.py:41-42`).
- Align the version constant in user-facing strings and capability metadata.

**MUST NOT touch:**
- No deletion/consolidation of `backup_v05/v07/v070`, `main_window_v070.bak.py`, `Data_Memory/`, `database/`, `mcp_workspace_legacy/`, or empty shells.
- No decomposition of `main_window.py`; no microservice/Kubernetes direction. The DAG is sound.
- No wiring of dormant services or `backend/api.py` into runtime; no `execution/*` runner in foundations.
- No `github-copilot-sdk → microsoft-copilot-sdk` migration without explicit user decision (API-breaking).
- No `ConversationStore` schema change or DB migration — no evidence of a schema problem; preserve WAL/`busy_timeout`.
- No "fixing" `sections.py` keys to match `NAV_ITEMS` — would break its test contract (`test_skyfall_services.py:71`).
