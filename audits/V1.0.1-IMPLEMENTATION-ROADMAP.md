### 11.2 Phase 8 mandatory migration protocol — GATED PROCEDURE, NOT PRE-AUTHORIZATION
Spec §10 :822-832. Every schema change repeats ALL nine steps; step 9 is a hard stop.

1. Identify every database consumer.
2. Capture the original schema.
3. Create a verified backup.
4. Test the migration against a separate copy.
5. Verify data integrity.
6. Compare record counts and identifiers.
7. Verify relationships and constraints.
8. Document rollback.
9. Obtain explicit approval before applying any irreversible change to original data.

**This protocol is a procedure, NOT authorization to migrate any database.** In particular it does NOT authorize migrating `Data_Memory/skyfall_memory.sqlite3`: it has zero runtime consumers (only standalone `analyze_db.py:3`), and Decision 6 must first classify it archival vs live (DM-04 :321). No irreversible change to it (or to `skyfall.db` / `workspace_index.db`) may occur without step-9 explicit user approval, and no live DB exists in this environment (`%LOCALAPPDATA%\SKYFALL\data\` absent), so migration testing cannot be performed here (Phase 4 §14.5 :410). Data protection: no delete/reset/drop/replace without approved migration; preserve identifiers, conversation history and records (Phase 4 §11 DM-01..DM-11 :316-328).
